# 画布多参绑定

画布工作流是用户确认的默认用途；具体平台节点是否接入，以可观察的画布状态、用户素材清单或用户明示为准。不能因为本轮聊天没附图，就推断用户画布也没有图。

## 四种实际输入

| 状态 | 处理 |
|---|---|
| 有用户明确的 @ 标签与职责 | 原样使用，能读则读，不能读也不猜外观 |
| 能访问用户指定画布或附件，但没有职责表 | 只读盘点素材／实际连入生成节点的引用，结合剧情映射；不声称仅凭空间邻近就已连接 |
| 有素材路径或清晰的节点名称，无平台标签 | 保留实际节点名称或按媒体类型建立别名，正文外简短说明上传／绑定对应；不假装节点已连接 |
| 只有剧本，未知任何素材编号 | 做完整“画布待绑定稿”，以语义槽位表示需要绑定的主角和场景；不造 @ 编号，不要求先上传才开工 |

如果工具无法读取画布，只使用已有信息。未授权的 UI 修改、生成点击或素材上传不属于提示词任务。

## 待绑定稿如何写

固定的一句说明：`画布待绑定稿：将〔名称〕替换为画布里的实际素材引用后使用。`

正文仍有完整的多模态参考层、全局设定、表演核心和分段剧本。例如：

```text
【多模态参考层】
女主的面孔、发型和衣着对应〔女主人物参考〕。
男主的面孔、发型和衣着对应〔男主人物参考〕。
餐厅布局、桌椅和空间关系参考〔餐厅场景参考〕。
```

这些括号只是在准备稿里方便绑定的标记，不是平台已经识别的引用。正文可以在人物重新入画时再次使用同一槽位。用户补充“女主图3、男主图1、餐厅图5”后统一替换为这些真实标签，不按模板顺序重新编号；删除待绑定说明。

只为需要保持一致的主要角色、重要场景及关键道具设置必要槽位。普通家具、车、话筒、群众等可由场景和文字承担；用户要求独立锁定时再设参考。声音没有参考需求时直接描述所需声音，不默认补一份音频。素材预算不足时优先主要角色和关键场景。

## 继承 sd25-pe 的映射纪律

1. 建立必需实体清单后浏览所有候选，不找到第一张相似图就停止。角色／群体各自选择最匹配的参考。
2. 用户明确绑定优先，已覆盖职责不自动添加另一张未指定图片。不同命名人物不合并；同一人的多视角不生成多个人。
3. 角色图仅锁定身份、外形和服饰。表演由剧情决定；与参考图的静态表情不同不等于换脸。
4. 场景图说明采用空间／光线、是否采用图中人物。动作视频只继承已指定的动作、机位、节奏等维度，不暗中复制原片人物。
5. 台词文字默认控制内容，音频控制音色、语速或用户指定维度；用户要求用音频原话时例外。多人分段逐人绑定。
6. 真实完整素材清单已知时，用 `【未采用素材】` 逐个列出未激活编号，写清不参与人物、场景、道具、动作、镜头或声音。只有待绑定槽位时不生成虚构的未采用列表。
7. 无法读取图片、视频或音频时保留已有引用；只根据文字写职责。不从名称或文件名猜外观、年龄、关系、音色和剧情。
8. 同一主体多份参考冲突时按用户指定分工；没有指定则依实际可见质量与职责判断。核心身份仍有多种等价解释时合并问一次；用户允许合理假设才采用。

## 素材内外的事实边界

人物名字、年龄、职业、关系和动机来自用户文本；外形可来自可读素材。新人物设计仅在用户授权时补充。身份未明时使用“人物／主体”，不把站姿推断成职业。

长段落中在换场、人物再入画、交接道具或变更说话人处重申关键绑定。参考层说明一次全片身份，具体阶段只激活会出场的主体，避免所有素材挤在每个镜头。
